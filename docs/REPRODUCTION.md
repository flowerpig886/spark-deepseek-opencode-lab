# 复现范围与材料边界

当前版本是配置与实测报告草稿，不是完整的一键部署或端到端评测发行版。

| 材料 | 当前提供 |
|---|---|
| 固定参数、环境、镜像/源码哈希 | 是 |
| 严格版本匹配的缓存修改脚本和Dockerfile | 是；仅做缓存层准备，不替代上游部署 |
| OpenCode 2.2.5基础接入示例 | 是；没有私有项目验证插件 |
| 六次仓库逐项结果、19次耐久记录、请求级数字 | 是；脱敏后导出 |
| 完整项目验证插件与Windows/Spark桥接发行版 | 未包含，路径解耦和授权说明尚需单独整理 |
| 模型权重、基础/派生镜像二进制 | 不提供；向上游获取/自行构建 |
| 隐藏测试、参考补丁、仓库完整源文件、原始会话 | 不随公开草稿分发 |

所以读者当前可以核对结果、借鉴参数和构建缓存层；不能只clone本仓库就重现4/6这个完整评分。基础OpenCode示例也没有被当作与项目专用插件完全等价的配置重新测试。

## 迁移顺序

1. 阅读上游模型卡与双Spark部署配方，使用固定版本；核对显存/统一内存、磁盘、互联和驱动。
2. 从模型发布方获取1017权重及匹配Engram，校验文件。不要把旧版GGUF和本EXL3方案混为一套。
3. 构建基础引擎；核对源码SHA256后准备单槽缓存层，保留原镜像。
4. 用上游配方启动、检查两rank和接口；分别验证文本、结构化输出、工具调用和缓存命中。
5. 接入隔离OpenCode配置，先在公开小项目里核实实际发送的low及32768输出参数。
6. 给自己的项目配置真实测试和独立验收。需要重复本报告评分时，等待完整桥接/插件发行材料或自行实现等价流程，并标明差异。

本地派生镜像标识不是公共Registry下载地址。主机的临时profile、密码本、SSH密钥及管理服务均属于原环境管理，不属于公开部署依赖。

## 数据可信度和溯源

公开数字来自固定的本地JSON/CSV，采用字段白名单导出；不是复制原始日志再全局替换字符串。`results/provenance.json`记录实验范围、私有完整归档的内容哈希和公开文件校验方法。私有归档不随本仓库上传，该哈希提供记录锚点，不能让读者凭哈希审计未公开内容。

`SHA256SUMS`只核验本草稿文件传输是否一致，不是第三方认证。初次公开前仍应完成[发布检查](../PUBLISH-CHECKLIST.md)。
